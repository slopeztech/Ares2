# Changelog — v2.7.1

**Date:** 2026-07-05  
**Type:** Patch (Driver)

---

## Summary

This patch adds startup static-offset compensation for the ADXL375 drivers
(I2C and SPI) to reduce constant axis bias in low-dynamic phases.

Observed field behavior before this patch showed one ADXL axis near ~3 g in
static conditions, which affected AMS logs and made threshold tuning harder.

The new flow calibrates raw offsets at startup and subtracts them from each
sample before converting to m/s².

---

## Changes

### ADXL375 startup bias calibration (I2C + SPI)

**Files:**
- `src/drivers/imu/adxl375_driver.cpp`
- `src/drivers/imu/adxl375_driver.h`
- `src/drivers/imu/adxl375_spi_driver.cpp`
- `src/drivers/imu/adxl375_spi_driver.h`
- `src/config.h`

Implemented:
- Added raw-axis startup calibration helper in both drivers:
  - `readRawAxesLocked(int16_t&, int16_t&, int16_t&)`
- Added per-axis raw bias state in both drivers:
  - `biasReady_`, `biasRawX_`, `biasRawY_`, `biasRawZ_`
- On successful `begin()`:
  - collect N startup samples,
  - compute per-axis average bias,
  - store bias and mark calibration ready.
- On each `read()`:
  - subtract calibrated bias from raw axis values,
  - then apply standard ADXL375 scale to m/s².

---

### New configuration knobs

**File:** `src/config.h`

| Constant | Default | Description |
|---|---|---|
| `ADXL375_BIAS_COMPENSATION_ENABLED` | `true` | Enables startup static-offset compensation |
| `ADXL375_BIAS_CAL_SAMPLES` | `32` | Number of startup samples used for bias estimation |
| `ADXL375_BIAS_CAL_SAMPLE_DELAY_MS` | `10` | Delay between startup samples |

---

## Operational notes

- Keep the vehicle static during boot for ~0.3–0.5 s so startup offset
  calibration captures a valid baseline.
- To return to raw ADXL behavior for diagnostics, set:
  - `ADXL375_BIAS_COMPENSATION_ENABLED = false`
