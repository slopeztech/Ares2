# Changelog — v2.7.4

**Date:** 2026-09-10  
**Previous version:** 2.7.3  
**Type:** Patch — safety hardening for pulse-fire authority

---

## Summary

This patch makes the AMS mission engine the single authority for `FIRE_PULSE_*`
actuation. Radio commands no longer access the pulse driver directly, preventing
a remote path from bypassing AMS validation, arm-token consumption, and mission
state preconditions.

## Safety fix

- Added `MissionScriptEngine::requestPulseFire()` as the common pulse-fire entry
  point.
- Centralized validation and atomic arm-token consumption in the AMS engine.
- Routed radio `FIRE_PULSE_*` commands through AMS and removed the dispatcher
  dependency on `PulseInterface`.
- Defined the remote-actuation contract in APUS-7.6, including NACK behavior for
  failed preconditions and execution failures.
- Updated AMS and APUS standards to document the single-authority invariant and
  operation ordering.

## Tests

- Added nine dispatcher tests covering pulse-fire authority, validation,
  arm-token handling, and rejection of bypass paths.
- Updated dispatcher, fragment-reassembly, and RX-buffer-guard fixtures for the
  new engine-owned pulse interface.
- Removed the obsolete standalone simulated pulse driver from the integration
  test path.

## Compatibility and residual risk

- The radio command names remain unchanged; only their execution path is
  hardened.
- Valid commands must continue to satisfy the AMS mission and arm-token
  preconditions before a pulse can be emitted.
- No wire-format change is introduced by this patch.

## Verification

The affected dispatcher and integration tests were updated for the new
engine-owned pulse interface. Full release validation remains tracked in the
project evidence for this version.
